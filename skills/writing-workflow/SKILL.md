# Writing Workflow

Start from the user's existing sources, brief, and draft. Choose the requested stage; do not restart a full project for a sentence edit or a humanizing pass. Preserve facts, author intent, SEO requirements, and already approved decisions.

For a full writing project, read [project workflow](references/project-workflow.md): storage, article classification, research risk, editorial gates, and deliverables. Resolve output location from the request, then project configuration, then `content-projects/` under the working directory. Check existing files before writing.

Load only the relevant stage:

| Task | Reference |
|---|---|
| Clarify a brief | [Briefing](references/content-briefing.md) |
| Choose an angle | [Topic selection](references/content-topic-selection.md) |
| Establish evidence | [Research](references/content-research.md) |
| Write from agreed material | [Drafting](references/content-drafting.md) |
| Improve structure and argument | [Polishing](references/content-polishing.md) |
| Adjust prose while preserving meaning | [Humanizing](references/content-humanizing.md) |
| Adapt a finished article | [Repurposing](references/content-repurpose.md) |
| Learn an explicitly supplied style | [Style learning](references/content-style-learning.md) |

Do not fabricate facts, quotes, numbers, or experiments. Separate author interpretation from sourced consensus. Review the resulting text for facts, structure, rhythm, title-body fit, and ending as applicable; do not repeat a completed check without a new change or unresolved concern.

Use an available image capability only when visuals are requested or needed for the agreed deliverable. Text work does not require installing image dependencies. Publishing or sending content requires existing authorization; saving a local draft does not imply publication.
